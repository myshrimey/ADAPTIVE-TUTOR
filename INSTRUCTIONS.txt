SAHAYAK v53 - diagnostic questions never repeat; the question bank grows by 50 every session start
Apply AFTER v52.

HOW TO PUT IT ON THE WEBSITE
1. Unzip. Copy every folder/file over your project folder ("Replace" when asked).
2. Supabase: open your project > SQL Editor > New query. Run the project's usual migration command (npm run db:migrate) OR paste the file packages/db/migrations/0028_question_bank_growth.sql and press Run. It is safe to run twice.
3. Deploy to Vercel the usual way. No new environment variables.

WHAT TO CHECK (10 minutes)
1. Sign in as a student who has done a diagnostic before; start the diagnostic for the same subject again. The questions should be ones the student has not been asked before (if the subject has run out of unseen ones, a new one is written; this may take a few seconds longer).
2. Start a learning session, wait a minute, then open /admin/question-bank. The subject shows "Owed" going down and "Written" going up. Press "Write what is owed" to carry on by hand (takes up to 45 seconds per press).
3. In /admin/reviews the new questions appear as AI-written and unreviewed.

HONEST STATUS
Tested with a practice database and a pretend AI: unseen questions preferred; a new question is written when all are seen; the oldest-seen is reused if the AI is down; 50 written per request; wrong-answer questions dropped by the second check; no double running; nothing lost when the AI is down. Build and type-check pass.
NOT tested: the real AI (speed, how often the second check rejects), the admin counts on your real Supabase.
Honest limits: on the free AI tier one run may write fewer than 50; the rest stays "owed" and continues at the next start. The second check catches many wrong answers but is not proof; teachers must still review. Questions are never repeated while an unseen one exists; if the bank and the AI both fail, the oldest-seen one is reused rather than leaving the student without a question.
