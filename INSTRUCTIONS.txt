SAHAYAK v54b - Tutor/Centre seats, parents buying for a child, paid reports, review statuses, read-aloud
Apply AFTER v54.

HOW TO PUT IT ON THE WEBSITE
1. Unzip. Copy every folder/file over your project folder ("Replace" when asked).
2. Supabase: run npm run db:migrate OR paste packages/db/migrations/0030_seats_entitlements_review.sql into SQL Editor and press Run. Safe to run twice. Do this BEFORE deploying.
3. Deploy to Vercel the usual way. No new environment variables.

WHAT IS NEW AND WHAT YOU DECIDE
1. Tutor/Centre plans: after you have checked a payment, go to /admin/partners, find the tutor/centre, press "Activate / renew paid plan (1 month)" and type the payment reference. Pressing again with the same reference does not extend twice. Their page then shows seats used and a pool of mock credits (20 for tutor, 50 for centre each month); they can press "Give 1 mock credit" next to a linked student.
   Seat LIMITS are OFF so nobody is locked out today. To switch on: /admin/pricing > setting "seats" > change "enforce":false to true. Then a tutor/centre without an active plan cannot add NEW students, and no one can go over the limit.
2. Parents: on a plan's buy page a parent now sees "This plan is for" with their linked children. The payment is recorded against that child; you verify it as usual at /admin/payments.
3. Paid reports: /board-readiness, /exam-rescue, /board-programme (and for parents: the links under each child on the parent page). Free users see what it is and a "See plans" button. Which features need a paid plan is the setting "entitlements" in /admin/pricing. To open everything to everyone during founding access, set "enforce": false.
4. Exam dates: /admin/pricing > setting "boards": type board1_date / board2_date as YYYY-MM-DD when you have them. Until then the programme covers the next 12 weeks and says so.
5. Handwritten papers now show a review status (AI evaluated / waiting for a teacher / reviewed by a teacher / failed / marked again). A failed run does not use a credit.
6. Read-aloud button under tutor messages (uses the phone/computer's own voice; free plan limit set in "free_limits" voice_per_day, default 5 a day).

WHAT TO CHECK (15 minutes)
1. Run the migration, open /admin/pricing: settings "entitlements", "seats", "boards" appear.
2. Sign in as a free student, open /board-readiness: you see the locked page. Give the student a paid plan (/admin/students) and refresh: the report shows.
3. As an approved tutor, link a student with a code, then in /admin/partners activate the plan; the tutor page shows the plan and "Give 1 mock credit" works; the student's credit goes up by 1 and the pool down by 1.
4. As a parent (linked child), open a plan buy page: child picker appears; submit a fake reference; see it in /admin/payments.

HONEST STATUS
Tested with a practice database: seat limit, activation and renewal (no double), monthly pool credits, giving a credit (once only, refused for unlinked/expired/empty), feature gating, daily voice limit, review status roll-up, rescue plan order (base skill before weak skill), programme weeks/checkpoints, parent payment record (45 checks). Migration runs twice cleanly on a real Postgres. Type-check and full build pass.
NOT tested: your real Supabase, the new pages in a real browser, a real tutor/parent sign-in, the real AI evaluation, the browser voice on Hindi.
HONEST LIMITS: "Visual interactions" limit is stored but no such feature exists. Board Readiness / Rescue / Programme use only recorded evidence, never predict marks, and have no separate purchase price yet (they come with any paid plan; a stand-alone price is your decision after the willingness-to-pay answers). Tutor/centre plans are activated by you by hand, no automatic renewal. Two separate Board 1 / Board 2 programmes arrive in v56.
