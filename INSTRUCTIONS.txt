SAHAYAK - v66 UPDATE  (traffic counter check)
Apply v65 (and everything before it) first.

WHAT HAPPENED
Your Website traffic page shows 0 although migration 0041 ran. So the table exists; something else stops visits being saved. The old code hid every error, so I could not see why from here. This update does not guess: it adds a button that tells you.

WHAT THIS UPDATE DOES
1. On Admin > Website traffic, at the bottom, there is a new "Check the counter" button. It reports in plain words:
   - whether the page counter is installed on the page (if NOT: the file apps/web/app/layout.tsx from the v64 zip was probably not copied - copy it again, it is the most likely cause);
   - whether your browser sends "Do Not Track" (then your own visits are not counted, by design);
   - whether the server has its database key, can read the traffic table, and can save a visit (it saves and removes one test row, and shows the database's own error message if it fails);
   - and it sends a test visit from your browser and says whether it was counted, or the exact reason it was not.
2. If the traffic table cannot be read, the page now shows the database's message at the top instead of just zeros.
3. A small safety migration 0042 that tells Supabase to refresh its list of tables (a table created by a migration is sometimes not visible to the website until this happens). It changes no data.

STEPS
1. Unzip over your project folder (replace files).   IMPORTANT: also check that apps/web/app/layout.tsx was replaced (open it: it should contain the word TrackPageView).
2. npm install
3. npm run db:migrate   (adds 0042; safe to run twice)
4. Deploy as usual.
5. Browse your own website's home page and a plans page in another tab for a minute, then open Admin > Website traffic and press "Check the counter".
6. Send me the lines it shows (a screenshot is fine). If it reports everything fine, press the date buttons again: visits should appear.
